# 鹰眼巡校——VisDrone 单数据集训练实验计划（论文版 V2）

> 版本说明：本版替代此前"三数据集混合"方案。按用户决策，**只用 VisDrone2019 一个数据集**（标注规范统一，杜绝多源标注噪声），基线 YOLO 同条件同步自训，论文主打**轻量化与 FPGA 部署优势分析**，不宣称精度超过大模型。所有数字必须来自真实运行的 `runs/` 输出，负结果如实写。

## 1. 论文定位与诚实边界

- 贡献点定位：面向边缘/FPGA 部署的无人机俯视人车检测系统——**精度-算力-部署友好性的权衡分析**，而非刷精度榜。
- 允许宣称：① 与**同条件自训**的 YOLOv8n 基线对比的提升/退化；② 轻量化指标（参数量、计算量、权重体积、FPS）相对大模型的优势；③ 量化鲁棒性（FP16/INT8 掉点幅度）对 FPGA 定点化的支撑。
- 禁止宣称：精度超过 YOLOv8s/m 等更大模型（除非实测真的超过，且同条件）；引用他人公开数据与自训数字混排进同一对比表（要么全自训，要么明确分列标注"引用"）。
- 口径红线：论文表格中每个数字可在 `runs/<实验名>/` 中找到对应 `results.csv` 与权重，允许复现。

## 2. 数据策略（只用 VisDrone2019）

- 数据集：VisDrone2019-DET，训练集 6471 张 / 验证集 548 张 / 测试集 3190 张，10 类（pedestrian, people, bicycle, car, van, truck, tricycle, awning-tricycle, bus, motor），单一团队单一标注规范，天然解决"标注不统一"顾虑。
- 获取：ultralytics 内置 `visdrone.yaml`，首次训练自动下载并按官方脚本转 YOLO 格式（约 2.3GB）；转换产物与官方一致，不自写映射，避免引入标注误差。
- **类别决策：训练与论文评估一律用原始 10 类**（保证与文献可比）；部署到巡检系统时，在推理输出后做 10→5 类映射（pedestrian+people→person、bicycle→bicycle、motor→motorcycle、car+van→car、bus→bus，truck/tricycle/awning-tricycle 丢弃），映射只发生在 `src/` 推理侧，不动训练标签。
- SDD/UAVDT 移出本计划：如二期需要，以"域适应微调"单独立项，不做混合训练。

## 3. 公平对比设计（同步训练）

论文里所有模型**同一训练集、同一验证集、同一 epochs、同一增强配置、同一 imgsz、同一台实例**自训，杜绝"拿官方预训练权重数字陪跑"的不公平对比：

| 角色 | 模型 | 训练条件 | 用途 |
|---|---|---|---|
| 基线 | YOLOv8n（COCO 预训练权重起步） | 完全一致 | 论文主基线 |
| 上限参照 | YOLOv8s（同样自训） | 完全一致 | 标出精度上限，反衬轻量化取舍 |
| 受试组 | YOLOv8n + 各增强配置 | 仅增强不同 | 消融实验 |

COCO 预训练 `yolov8n.pt` 只作为初始化权重出现，其 COCO 精度数字不进入论文对比表。

## 4. 实验矩阵

统一训练参数（除受试变量外）：`imgsz=960`、`epochs=100`、`batch` 按实例显存取 16~32（全程记录实际值）、`optimizer=auto`、`patience=20`、`multi_scale=True`、`cos_lr=True`、AMP 开启、随机种子固定（seed=0）。

| 编号 | 实验 | 变量 | 预期产物 |
|---|---|---|---|
| E0 | 基线复训 | YOLOv8n + 默认增强（mosaic=1.0, fliplr=0.5, 轻 HSV） | 基线 mAP，`runs/e0_baseline/` |
| E1a | 旋转增强 | `degrees=10` 与 `degrees=30` 两组（俯视无固定朝向） | 消融行 1 |
| E1b | 切割类增强 | `cutout=0.3`（随机遮挡切块）对照 E0 | 消融行 2 |
| E1c | 反转色 | Albumentations `InvertImg(p=0.2)`（模拟红外/负片光照）对照 E0 | 消融行 3 |
| E1d | 小目标增强 | `copy_paste=0.1` 对照 E0（文献中对俯视小目标增益最明显的一项） | 消融行 4 |
| E1e | 最优组合 | E1a–E1d 中**实测有效**的项组合 | 论文主模型 |
| E2 | 大模型参照 | YOLOv8s，套用 E1e 最优组合 | 精度上限参照行 |
| E3 | 轻量化对比 | E0/E1e/E2 三个模型：参数量、GFLOPs（imgsz=960）、FP32/FP16/INT8 权重体积、实例 FPS 与本机 RTX 3060 FPS | 论文轻量化主表 |
| E4 | 量化鲁棒性 | E1e 模型导出 FP16 / INT8（PTQ，校准集取验证集 548 张），测 mAP 掉点 | FPGA 可行性证据 |
| E5 | FPGA 友好性分析 | 统计 E1e 算子构成（Conv/BN/激活占比、有无动态 shape）；BN 折叠后参数量；可选加做"SiLU→ReLU"重训对照（FPGA 对 ReLU 支持最好），如实报告该替换的精度代价 | FPGA 部署基础分析小节 |
| E6 | 系统级验证 | E1e 权重 → `weights/best.pt`，跑 `tools/evaluate.py`（farm_guard 两段素材），与 A10 报告 COCO 权重结果同口径对比（检测成功率/误检率/漏检率） | 论文"系统验证"一节 |

不做实验清单（避免范围蔓延）：不引入 P2 小目标头、不换主干网络、不做剪枝蒸馏（可作为"未来工作"写进论文）。

## 5. 评估指标体系

- 精度：mAP50、mAP50-95（验证集 548 张，ultralytics `val` 直接产出）；附 per-class AP 表（10 类）。
- 速度：实例上纯推理 FPS（batch=1，imgsz=960，FP32/FP16 各一组）+ 本机 RTX 3060 Laptop 同口径 FPS。
- 轻量化：参数量（M）、GFLOPs、权重文件体积（MB，FP32/FP16/INT8 三档）。
- 部署：INT8 相对 FP32 的 mAP50 掉点（百分点）；算子兼容性清单。
- 系统：检测成功率 / 误检率 / 漏检率（沿用 A10 代理口径，数字与 `tests/` 落盘 JSON 一一对应）。

## 7. 代码与数据备份方案

1. 训练开始前：项目 `git init`（若尚未），建私有远端（GitHub/Gitee 私有仓），`.gitignore` 排除 `weights/`、`runs/`、`data/`、`archive/`、`reference/`；推送一次基线提交。**git 操作由用户确认后执行**。
2. 实例侧：代码用 `git clone` 拉取，实验分支命名 `exp/visdrone-v2`；每次实验完成后提交配置与脚本改动并 push。
3. 产物回传：每次实验结束，用 `rsync -avz -e ssh`（或 `scp`）把 `runs/<实验名>/` 与产出权重拉回本机 `archive/exp_backup/<日期>/`；**实例关机/释放前必须完成回传**（实例释放后数据不可恢复）。
4. 实验登记：每跑一次，在 `docs/实验登记.csv` 追加一行（日期、实例型号、实验编号、配置摘要、runs 路径、验证集 mAP50/mAP50-95、备注），论文表格直接从该 CSV 取数，杜绝记忆填数。

## 8. 预期效果（区间估计，以实测为准）

- E0 基线：YOLOv8n@960 在 VisDrone 验证集 mAP50 约 0.33~0.40、mAP50-95 约 0.19~0.24（文献区间，自训可能略低）。
- E1 消融：copy-paste 预期 +0.5~1.5 点 mAP50；旋转 +0.3~1 点；cutout 小幅正负皆可能；**反转色大概率无效甚至掉点**——若如此，如实写"该增强对俯视可见光场景无增益"，这本身就是消融的价值。
- E2：YOLOv8s 预计比 n 高 3~6 点 mAP50——这就是"比不过"的部分，论文里用它反衬：n 的参数量/GFLOPs/INT8 体积约为 s 的 1/3.5，FPS 高约 2 倍。
- E4：INT8 PTQ 掉点预期 1~2 点 mAP50 以内；若掉点 >3 点，如实报告并改述为"需 QAT 的后续工作"。
- E6 系统级：相对 A10 的 COCO 权重（15 米档成功率 0.8254、漏检 0.1247、10 米档 sheep/cow 误检），微调权重预期成功率升至 0.90 上下，10 米档"弯腰人误检为羊/牛"问题应消失——这组对比是论文最有说服力的系统级证据。
- 结论话术预案：若 E1e 超 E0 → "轻量模型 + 合适增强即可在目标域逼近大模型，且部署友好"；若 E1e 持平 E0 → "默认增强已接近 nano 容量上限，论文转向部署优势论证"。两种结果都有话可写，均不造假。

## 12. GitHub 发布与命名（调研结论 260923）

同类项目命名主流为 `{领域/任务}-{模型}` 全小写连字符英文（如
`Drone-Detection-YOLOv8x`、`UAV-River-inspection-YOLO`、`uav_det`、
`YoloV8-VisDrone`）。GitHub 搜索索引仓库名/描述/topics，Google 索引 README，
采用社区通用术语命名可显著提升被搜索到的概率。

- 仓库名（已定，260923）：`yolov8-drone-campus-patrol`——去产品化纯关键词命名，
  yolov8/drone/campus/patrol 均为高频搜索词；品牌名 Eagle Eye 仅保留在 README 标题；
- topics：`yolov8` `visdrone` `uav` `drone` `object-detection`
  `small-object-detection` `campus-security` `bytetrack` `edge-deployment` `fpga`；
- README 中英双语，英文段覆盖检索关键词；
- 许可证（已定，260923）：仓库采用 AGPL-3.0（ultralytics 为 AGPL-3.0，避免许可证冲突）；
- 不提交内容（已定，260923，已写入项目根 `.gitignore`）：weights/、数据集 data/、
  运行产物 archive/ runs/ logs/、第三方资料 reference/ 与 hw7.pdf、视频文件。
