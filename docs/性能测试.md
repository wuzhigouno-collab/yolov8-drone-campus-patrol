# 鹰眼巡校——A13 推理加速 性能测试报告

## 1. 测试目的

量化 A13 推理加速两项优化（FP16 半精度推理、跳帧检测+ByteTrack 轨迹外推）
的真实收益：对同一视频分别运行"优化前"与"优化后"两组巡检管线
（检测 + ByteTrack 跟踪 + 多帧确认，与 `src/app.py` 跟踪路径同源），
对比实测处理帧率（FPS）与检出数。

## 2. 测试条件

- 测试命令（数据全部来自该命令真实运行输出，原始日志 `tests/a13_benchmark.log`、
  结构化结果 `tests/a13_benchmark.json`）：

  ```
  python tools/benchmark.py --video "C:/Users/OS/Desktop/farm_guard/videos/5G智慧农业素材.mp4" --max-frames 300 --interval 3 --out tests/a13_benchmark.json
  ```

- 测试视频：`5G智慧农业素材.mp4`（1920×1080，25 fps，全片 3712 帧；
  本次两组均只处理前 300 帧，帧数上限由 `--max-frames` 控制，保证两组
  处理完全相同的帧序列、结果可重复）
- 运行环境：Windows，torch 2.12.1+cu126；CUDA 可用，
  GPU = NVIDIA GeForce RTX 3060 Laptop GPU（本机有 N 卡，
  故 FP16 半精度在优化组实际生效，适用综合提升 ≥30% 达标线）
- 计时口径：逐帧"读帧 + 检测/跟踪/外推"全链路墙钟时间；模型加载与
  首帧跟踪器初始化已预热剔除，两组口径一致
- 检出数口径：全部处理帧的目标记录总数与帧均检出（优化前 300 帧全部
  为实测；优化后检测帧 100 帧为实测、中间 200 帧为轨迹外推渲染）
- 分组配置：
  - 优化前（基线组）：`fp16=False`（FP32 全精度）+ `detect_interval=1`（逐帧检测）
  - 优化后（加速组）：`fp16=True`（本机实际生效 FP16）+ `detect_interval=3`
    （每隔 3 帧检测一次，中间帧按轨迹实测速度线性外推）

## 3. 实测结果

| 组别 | 配置 | 帧数 | 耗时(s) | FPS | 检出总数 | 帧均检出 |
|------|------|------|---------|-----|----------|----------|
| 优化前 | FP32 + 逐帧检测(间隔1) | 300 | 7.36 | 40.79 | 63 | 0.210 |
| 优化后 | FP16 + 跳帧间隔3 | 300 | 4.03 | 74.50 | 57 | 0.190 |

- 优化后检测帧 100 帧实测检出 19；确认事件数：优化前 4 / 优化后 2
- **FPS 提升：+82.6%**（达标线 ≥30%，有 CUDA 看综合提升）：**达标**
- **帧均检出数变化：-9.5%**（允许下降 ≤10%）：**达标**
- benchmark 退出码：0（整体判定达标）

## 4. 结论与分析

1. 开启 A13 优化后，处理帧率由 40.79 FPS 提升至 74.50 FPS（+82.6%），
   远超 25 fps 的素材帧率，实时巡检有充足裕量；加速主要来自跳帧——
   模型推理只在 1/3 的帧上发生（300 帧中仅 100 帧推理），FP16 半精度
   在 RTX 3060 Laptop GPU 上叠加贡献少量提升。
2. 帧均检出数下降 9.5%（0.210 → 0.190），在 ≤10% 允许范围内。下降的
   构成：跳帧后 ByteTrack 关联的观测间隔变长，个别弱目标轨迹未能接续，
   确认事件由 4 减至 2；中间帧目标位置由轨迹外推渲染维持，画面目标
   显示不中断。
3. 无 N 卡环境的预期行为：FP16 由 `src.detector.resolve_fp16` 自动降级
   为 FP32 并记日志说明（降级逻辑由 `tests/test_accel.py` 单测覆盖），
   此时加速仅由跳帧单项贡献，按验收标准跳帧单项提升需 ≥50%。
4. 复现方式：按第 2 节命令重跑即可，帧数上限固定为 300，输出以当次
   实测为准。
